Autonomous agents can lose track of payments due to crashes, network timeouts, or retry failures. Payment reconciliation compares the agent's local payment records against onchain transaction history to detect missed, duplicate, or failed payments.

## Querying transaction history

List the agent's finalized transactions with the gRPC client's `listTransactions` method, filtered by sender:

Results are cursor-paginated in ledger order. Persist `endCursor` between reconciliation runs so each pass scans only transactions added since the last one.

## Verifying individual payments

A digest in the sender's history proves the transaction is final; it does not prove the payment succeeded or paid the right party. Fetch the transaction's balance changes and match them against the payment the agent intended to make:

<ImportContent source="examples/onchain-finance/payment-reconciliation/src/reconcile.ts" mode="code" tag="verify-payment" />

Balance changes report each address's net change per coin type, so a payment transaction also produces entries that are not payments: the sender's own debit and storage rebates credited back to the sender. Matching on the expected recipient and coin type avoids misclassifying those artifacts as payments.

## Real-time monitoring with checkpoint subscriptions

The gRPC `SubscriptionService.SubscribeCheckpoints` streams checkpoints as the network finalizes them. Filter the stream to checkpoints that contain the agent's transactions and feed each matching transaction into the reconciliation state:

<ImportContent source="examples/onchain-finance/payment-reconciliation/src/reconcile.ts" mode="code" tag="subscribe-checkpoints" />

Subscriptions always begin at the current tip of the chain and do not support resumption. Persist the last received cursor; after a disconnect, replay the missed range with `LedgerService.ListCheckpoints` (same filter, `startCheckpoint` of cursor + 1) before re-subscribing.

For event-level filtering, use a [custom indexer pipeline](/develop/accessing-data/custom-indexer) built on the `sui-indexer-alt` framework. The indexer processes checkpoints and writes matching events to your database.

## Production reconciliation

For production agents processing high volumes, use a [custom indexer](/develop/accessing-data/custom-indexer) built on the `sui-indexer-alt` framework. The indexer continuously processes checkpoints and writes payment data to your database, giving you a complete, queryable history without polling the RPC.
